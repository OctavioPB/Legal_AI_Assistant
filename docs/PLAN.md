# PLAN.md — Legal AI Assistant: from zero to a working demo

States (implicit column; marked in the ID or in the Log): `[ ]` pending · `[~]` in progress ·
`[x]` done · `[-]` discarded (with an ADR or note). **Active phase: WS0 → WS3** (WS1 done and tested against a real Postgres; WS2 logical core in progress `[~]`; WS0.T01/T04–T10 pending).
Ordering principle: first a retriever **measured without an LLM**, then generation on top of a
retrieval layer that has already proven its value. Every measurement records both numbers (before/after).

Conventions:
- **WS** = workstream · **T** = task with a stable ID (`WS.T##`) to reference in PRs/issues.
- `deps:` tasks that must exist first. `DoD:` verifiable Definition of Done.
- **Cross-cutting UI rule:** all Frontend/UI development (components, layouts, colours,
  typography, microcopy, empty states, citation rendering) **must obey `Brand.md`**
  (`docs/`). No UI PR is merged without declaring conformity with `Brand.md`;
  if `Brand.md` does not cover the case, `Brand.md` is extended first, nothing is improvised in the component.

Scope of the working demo (global exit criterion):
one firm (a real tenant) + a seeded public corpus (federal LFT, Código Civil NL,
1 Monterrey municipal bando, 1 US/CA statute), a bilingual session with a
jurisdiction and persona selector, Dossier Builder and Adversarial Counterpart operating with verified
citations, a structured refusal visible in the UI, and golden suite v1 green.
